# وثيقة 12 — نظام التشغيل والأتمتة (كيان شخص واحد قابل للصمود)

> **الهدف:** أن يعمل النظام بلا ذاكرة في رأس المؤسس — حتى يستمر بالجودة لو توقف أسبوعاً، أو فُوّض لاحقاً.
> **المكونات:** إيقاع تشغيل أسبوعي + مكتبة أوامر ذكاء اصطناعي (`templates/ai_prompts.md`) + أرشفة + صمود.

---

## 1. الإيقاع التشغيلي الأسبوعي (حلقة مغلقة)

| اليوم | العملية | المخرج الموثق |
|---|---|---|
| **السبت** | 1) مراجعة أرقام الأسبوع (10 د) 2) اختيار موضوعات الأسبوع من القاعدة 3) فتح ملفات المصادر | سطر واحد في سجل KPI + معرفات موضوعات مجدولة |
| **الأحد–الخميس** | إنتاج وفق التقويم (`calendar/90day_calendar.csv`) | المنتجات + سجل التحقق (`templates/verification_log.csv`) |
| **الخميس مساءً** | تجميع المشتقات للأسبوع القادم (كاروسيل/خيط) | مسودات مشتقات جاهزة |
| **الجمعة** | راحة — أو استطلاع تفاعل كل أسبوعين | — |
| **نهاية الشهر** | مراجعة KPI الشهرية + قرار استبدال/استمرار | تقرير داخلي صفحة واحدة |

**قاعدة الحلقة:** لا منتج يُنشر دون (مصدر موثق + وسم تحقق + رقم موضوع). وثلاثة منتجات متتالية دون أرقام → توقف وحدّث النظام لا المحتوى.

## 2. طابور المصادر الدائم

- **مجلد `_raw/sources/`:** ملف لكل تقرير/نشرة رسمية يُستخدم (GASTAT، ZATCA، الهيئة الملكية، الأمانة، واس) مع تاريخ التنزيل والرابط.
- **قائمة متابعة شهرية:** إشعارات النشرات الشهرية الرسمية (رخص البناء، تكاليف البناء، مؤشر أسعار العقارات، إحصاءات العمرة) — يفحصها المؤسس أول سبت كل شهر.
- **قاعدة الصياغة:** كل رقم يُخزن بصيغته: (الرقم — النطاق — تاريخ الإعلان — الرابط) — نسخة واحدة تُستخدم في كل المنتجات، فلا تتناقض التواريخ بين قناة ومنصة.

## 3. الأتمتة: ماذا نؤتمت وماذا لا نؤتمت

| تُؤتمت بالكامل | تُؤتمت مع مراجعة بشرية | لا تُؤتمت أبداً |
|---|---|---|
| تجميع الأرقام من النشرات إلى ورقة واحدة | المسودات (بأوامر المعتمدة) | الصياغة النهائية والنبرة |
| تنسيق الكاروسيل من قالب | الترجمة/إعادة الصياغة | الحكم على المصدر الموثوق |
| جدولة النشر المسبق | ملخصات التقارير الطويلة | أي رقم يُنشر دون تدقيق يدوي بتاريخه |
| سجلات KPI والتحقق | | المواقف الحساسة (تعويضات، نزاعات) |

> **حوكمة الأدوات:** لا تُرفع مستندات عملاء أو عقود إلى أدوات خارجية دون تحقق من سياسة البيانات؛ المستندات العامة والقوالب فقط هي ساحة الأتمتة.

## 4. مكتبة الأوامر الذكية

كاملة ومنظمة حسب نوع المنتج في: `templates/ai_prompts.md` (أوامر A1–A12 للمقال، B للمشتقات، C للتحليلات، D للمراجعة والتحقق). قاعدة الاستخدام: **الأداة تسود وتبني — البشر يقررون وينشرون.**

## 5. الأرشفة والاسترجاع

- **بنية مجلدات ثابتة:** `/content/2026-11/الأسبوع-1/` — كل منتج ملف باسمه: `TG-مقال-7نقاط-صب-سقف-P1-001.md`.
- **سجل التحقق ملف واحد تراكمي** — لا نسخ متفرقة؛ هو الذاكرة القانونية للقناة.
- **أرشفة شهرية:** نسخة CSV من التقويم بعد التحديث الفعلي (تم/تأجل/استُبدل) — تحفظ ما حدث لا ما خُطط.

## 6. خطة الصمود (Business Continuity)

| السيناريو | البروتوكول |
|---|---|
| مرض/سفر 3–7 أيام | مخزون الأمان (مقالان + 3 منشورات) يُنشر آلياً؛ إعلان صادق «أرشيف هذه الأسبوع» |
| توقف أسبوعين+ | توقف صريح مُعلن + خطة عودة بأسبوع كامل، لا نشر غائب صامت |
| انسحاب محتوى (خطأ وثّقناه) | التصحيح بنفس بروز الخطأ + إضافة للسجل — الشفافية أصل تجاري |
| حساب محظور/مفقود | نسخ احتياطي شهرية لكل المنتجات + قائمة اتصال طوارئ في إحدى المنصات الأخرى |
| تفويض مستقبلي | هذه الوثيقة + 07 + 09 + أوامر AI = دليل تشغيل كامل لشخص بديل |
